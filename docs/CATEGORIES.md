# Categories

A category is one record, and it is data — not a hardcoded list and not a
stylesheet:

```js
{ id, label, color, colorDark, order }
```

| Field | Rule |
|---|---|
| `id` | **Stable forever.** Never shown to a human. Changing it detaches every source using it. |
| `label` | Display text. Rename freely — nothing points at it. |
| `color` | Signal Desk stripe + label colour, light theme. |
| `colorDark` | The same hue lifted for a dark ground. |
| `order` | Nav position. |

**The invariant:** a source stores `category: '<id>'`, never a label. That is
what makes rename and recolour safe.

> `colorDark` is an addition to the `{ id, label, color, order }` shape. One hex
> cannot serve both themes — a colour readable on white is muddy on `#0f0f0f` —
> and dark mode has to keep working. Picking a palette entry sets both.

---

## The migration

**Zero source edits. Zero data loss. 46/46 sources kept their category.**

The refactor was smaller than it looked, because the strings already on sources
(`category: 'energy'`) were *always ids* — the human-readable labels lived
separately in `CATEGORIES`. Nothing pointed at display text to begin with.

What actually moved:

| Before | After |
|---|---|
| `CATEGORIES` in `config/sources.js` — id + label only | `config/categories.js` — the full record |
| Colours hardcoded in `app/globals.css` as `--cat-energy: #2f6b6b` | `color` / `colorDark` on the record |
| `[data-cat="energy"] { --cat: … }` written by hand per category | Generated by `categoryStyleSheet()`, injected in `layout.tsx` |
| Nav order = array order | Nav order = `order` field, via `sortedCategories()` |

The colour move is what makes the manager possible: a category added at runtime
had no colour before, because its CSS rule did not exist and could not be
written without editing a stylesheet.

`config/sources.js` re-exports everything from `config/categories.js`, so every
existing importer kept working and there is still exactly one definition.

### Verifying it

```bash
npm run categories:verify
```

Checks that every source resolves to a real category id, ids are unique, the
fallback (`general`) survives, and every category is renderable. Run it after
any category edit — a detached source is silent otherwise; the item just stops
appearing under any tab.

---

## The seeded eight are defaults, not fixtures

Every one can be renamed, recoloured, reordered, merged or deleted like any
category you add. One exception: **`general` cannot be deleted**, because it is
the reassignment target of last resort for delete and merge.

## Editing

The category manager lives in the customization tab (**Sources → Categories**).
It writes to `config/categories.js` through `/api/categories`, the same way
`/api/sources` writes sources: one writer, one file, no parallel list.

Delete and merge **always reassign** — you choose a target, or sources fall back
to General. Nothing is ever orphaned.

## Adding a colour

Pick from `PALETTE` in `config/categories.js`. Muted, editorial, never neon;
every light value clears 4.5:1 on white so a category label reads as text rather
than decoration. Twelve entries: the original eight plus four spares.
